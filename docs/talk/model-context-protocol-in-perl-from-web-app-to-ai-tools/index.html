Model Context Protocol in Perl: From Web App to AI Tools

talk

Description

The Model Context Protocol (MCP) has rapidly become the standard way for AI assistants to interact with external applications. But how do you add MCP support to an application that already exists?

In this practical workshop we'll take a real Dancer2 application and add an MCP server that exposes its existing functionality to AI clients. Along the way we'll look at the MCP protocol, JSON-RPC, tool discovery, schema design and request handling, while keeping the implementation cleanly separated from the application's existing business logic.

We'll see how a YAML-driven design allows a single source of truth for tool definitions and documentation, and why adding MCP often turns out to be far less work than you'd expect when your application's architecture is already sound.

By the end of the session you'll understand the MCP protocol, know how to implement an MCP server in Perl, and have a design you can adapt to your own applications.

This talk explores how an existing Perl web application can become a useful tool for AI assistants by adding support for the Model Context Protocol (MCP).

The example is Line of Succession, a Dancer2 application backed by SQLite that provides current and historical information about the British royal succession. Its most important architectural feature is a separate domain model: database access and succession calculations live outside the routes and templates. That separation makes it straightforward to add an AI interface without duplicating the application’s core logic.

The talk introduces MCP’s initialisation, tool discovery and tool invocation operations, then follows requests through the implementation. Two tools expose existing model methods: finding the sovereign on a particular date and retrieving the line of succession. A shared YAML file supplies tool descriptions and input schemas for both machine-readable discovery and the website’s documentation.

The code walkthrough covers Dancer2 routes, JSON-RPC request and response envelopes, request IDs, argument validation and error handling. Tool results provide both readable text and structured data, giving clients flexibility in how they use the answers.

Live demonstrations use small shell scripts to call the service, then connect it to Claude so that natural-language questions trigger the appropriate tools. Historical results are compared with the website, demonstrating that both interfaces use the same underlying model.

The central lesson is that a well-designed domain model makes new interfaces easier to build. Possible next steps include adopting a CPAN JSON-RPC implementation, adding more tools and extracting reusable MCP scaffolding into a Dancer2 plugin.
